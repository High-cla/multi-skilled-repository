# game-item-spawner 数据来源与再分发声明

## 仓库包含什么

本仓库提供通用的提取/转换脚本、localhost HTTP 服务器模板、网页模板、mock 服务和评测用例。仓库**不随附**游戏 DLL、游戏资产或某款游戏的完整物品目录。assets/items_data.js 是本地生成文件，应由使用者从其有权访问的游戏资源构建；默认不提交到版本库。

## 来源记录要求

每次生成或发布物品目录时，至少在项目自己的发行说明或 catalog-provenance.json 中记录：

- 游戏名称、发行商/权利方及游戏版本或构建号。
- 原始资源的相对路径、资源名称，以及原始 DLL/资源文件的 SHA-256。
- 使用的提取脚本版本、命令参数、提取日期（UTC）和转换脚本版本。
- 目录字段的来源（原始 JSON 字段、人工补充、翻译或分类规则）。
- 适用的 EULA、许可证、授权或其他再分发依据；无法确认时标记为“仅本地使用，未获再分发授权”。
- 对数据所做的删减、转换、翻译或人工修订。

示例清单（按实际情况填写，不要照抄虚构值）：

```json
{
  "game": {
    "name": "填写游戏名称",
    "version": "填写版本或构建号"
  },
  "source": {
    "resource": "本地资源相对路径或资源名",
    "sha256": "填写原始文件 SHA-256"
  },
  "generated": {
    "extractor": "extract_catalog.py",
    "converter": "json_to_js.py",
    "dateUtc": "YYYY-MM-DD"
  },
  "rights": {
    "basis": "填写 EULA/许可证/授权依据",
    "redistribution": "not-authorized"
  },
  "transformations": []
}
```

## 网页展示

网页模板不得暗示目录数据由本仓库创作或已获再分发授权。实际部署时应将来源说明、权利方要求的署名和适用许可证与数据一同展示。目录中的名称、描述、分类和 ID 都视为不可信输入，必须通过 DOM 的 textContent 等安全 API 展示，不得拼接进 HTML。
